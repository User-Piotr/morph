# morph

Agent setup for Claude Code: the `morph` core plugin, domain plugins, the
policy in `claude/` and the installer. `docs/reference.md` explains what lands
where and why.

## Conventions (agent-maintained)

### Public repository
- This repository is public: no company names, hosts, organisations, project or repository names, account names or internal URLs in any file, test or example. Examples use `example-team`, `grafana.example.com`, `team`.
- Plans live in `.claude/plans/`, which is git-ignored, and are never committed.

### Publishing
- Machine-specific publishing details (which account, which credential helper) belong in your own `CLAUDE.local.md`, which is git-ignored; start it with `@AGENTS.md` so this file still loads.
- Tag a release from `origin/main` after `git fetch`, never from a local `main` that may not have pulled: `git tag vX.Y.Z origin/main`, then push the tag and `vX.Y.Z:refs/heads/stable`.

### Settings
- `~/.claude/settings.json` is generated by `install.sh` from `claude/settings.json` (the shared template) and `~/.claude/settings.personal.json` (personal, outside the repository); personal plugins and marketplaces belong in the overlay, never in the template.
- `claude/settings.json` and the generated settings files are write-protected for agents; hand their edits to the user as an exact diff.
- Close every Claude Code session before moving or renaming the clone, then rerun `./install.sh` from the new path; `~/.claude` still links `CLAUDE.md` and the guard scripts into the clone, so a running session silently loses the mutation guards.

### Shell and tests
- Run `shellcheck --severity=warning` on every changed `*.sh` before pushing; CI fails on warnings (e.g. SC1087: brace a variable followed by `[`, `"${name}[${extras}]"`; SC2115: `rm -rf "${dir:?}/…"`).
- A hook that reads jq output with `mapfile < <(jq …)` cannot see jq fail; build the whole result inside jq before anything prints, and give `claude/tests/guards.sh` a row where a later entry errors.
- The Bash guard always allows `git push --dry-run`, so a live check of a guard verdict uses a real `git push origin HEAD` in a scratch repository with no remote.

### Installer and versions
- Removing and re-adding a marketplace does not touch installed plugins; `install.sh` runs `claude plugin update` for present ones, and a release check reads both versions from `~/.claude/plugins/installed_plugins.json`.
- `uv tool install --force` replaces the whole tool environment, so a pin without its extras drops them; tool pins and their extras live in `versions.env`, and `claude/tests/versions.sh` checks every JSON copy.
- A change under `plugins/<name>/` needs a `version` bump in its `plugin.json`; the CI `versions` job fails without it.
